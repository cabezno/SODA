# Learnings from sitio
*2026-04-21*

## Pattern: Static Site for Simple Interactions
Utilizing a purely static HTML/CSS approach for a single-page contact site proved highly effective. This minimized complexity, reduced hosting requirements, and accelerated development for a clear, self-contained functional need.

## Pattern: Leveraging Third-Party Services for Form Submission
Delegating form submission processing to a third-party service significantly simplified the project. It eliminated the need for a custom backend, database, and associated security/maintenance overhead, perfectly suiting a static site requirement.

## Pattern: Modular CSS Structure for Frontend Organization
Dividing CSS into `global.css`, `presentation.css`, and `form.css` allowed for a clear separation of concerns, improving stylesheet maintainability, readability, and making it easier to manage specific design elements even for a single-page application.

## Preference: Prioritization of Lean & Maintainable Stacks
The choice of a static site with no custom backend and reliance on third-party services indicates a strong preference for minimal, efficient, and easily maintainable technology solutions when project requirements allow.

## Preference: Commitment to User-Centric Design
Consistent emphasis on 'diseño moderno y adaptativo,' 'tipografía legible,' and a 'experiencia de usuario agradable' throughout the blueprint and project description reveals a deep-seated preference for delivering high-quality user experiences.

## Preference: Structured Frontend Codebase
The explicit modularization of the architecture (Infrastructure, Presentation, Form Functionality) demonstrates a preference for organized, well-structured frontend codebases that promote clarity and scalability, even in small projects.
