## Pattern: Hybrid REST/WebSocket Communication
Using a REST API for stateful operations like authentication, profile management, and chat creation, while reserving WebSockets specifically for high-frequency, real-time message delivery is a highly effective and scalable pattern for chat applications.

## Pattern: Feature-based Modular Architecture
Structuring the application into distinct feature modules (Auth, Users, Chats), each with its own router, schema, and service/CRUD layer, works very well for FastAPI. It keeps the codebase organized, maintainable, and easy to extend.

## Pattern: JWT with Refresh Tokens for Mobile
The JWT access/refresh token flow is a robust authentication pattern for mobile clients. It allows for long-lived sessions without requiring the user to constantly re-authenticate, which is critical for a smooth user experience in a messaging app.

## Anti-pattern: Inappropriate Database for High Concurrency
Using SQLite for a real-time messaging backend is an anti-pattern. A chat application involves frequent writes and concurrent connections, which will quickly overwhelm SQLite's file-locking mechanism. A client-server database like PostgreSQL is required for this use case.

## Anti-pattern: Naive Static File Handling for Media
Storing user-uploaded media as local static files on the API server is not scalable or resilient. This approach complicates deployments, backups, and scaling. A dedicated object storage service (like S3 or MinIO) should be used instead.

## Preference: Pydantic-driven Data Contracts
The consistent use of `schemas.py` in every module indicates a strong preference for defining explicit data contracts for API requests and responses. This leverages Pydantic for automatic validation and API documentation.

## Preference: Layered Abstraction (Router-Service-CRUD)
The design shows a clear preference for a layered architecture that separates the API interface (routers) from business logic (services) and data access (CRUD). This improves testability and separation of concerns.

## Knowledge Suggestion
Implementing and managing WebSocket connections in FastAPI, including connection lifecycle, broadcasting messages to specific clients or groups, and handling authentication over the WebSocket protocol.
