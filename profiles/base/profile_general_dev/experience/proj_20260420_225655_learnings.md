# Learnings from proj_20260420_225655
*2026-04-20*

## Pattern: LLM Task Decomposition
Breaking down the broad 'analyze the conflict' request into specific, parallel LLM prompts for different dimensions (political, economic, social, Uruguay-specific) was highly effective. It produces structured, categorized output that is much easier to manage and display than a single monolithic summary.

## Pattern: Aggressive Caching for LLM Results
The decision to include a Redis cache for LLM outputs is a crucial pattern for this type of project. Since the analysis is performed on a fixed set of news articles, caching prevents redundant API calls, significantly reducing both cost and latency for users viewing the dashboard.

## Pattern: Data Pipeline over Direct Opinion
The system successfully transformed a subjective user request for an 'opinion' into an objective, automated data pipeline (Ingest -> Analyze -> Visualize). This is a strong pattern for creating scalable, data-driven analysis tools that continuously update based on new information.

## Preference: Modular, Service-Oriented Backend
The architecture shows a clear preference for a modular backend with single-responsibility services (Persistence, Cache, Ingesta, Analysis). This avoids a monolithic script and favors a maintainable, scalable system where components can be developed and tested independently.

## Preference: Structured Data Transformation
There is a preference for using the LLM not just for summarization, but as a tool to transform unstructured text (news articles) into structured data that can be stored, categorized, and queried in a relational database. This makes the insights far more powerful for visualization and trend analysis.

## Preference: Separation of Data I/O from Core Logic
The design distinctly separates modules that handle data I/O (database, scraping, external APIs) from the core business logic in the `Análisis LLM` module. This clean separation is a preference that simplifies testing, debugging, and future modifications to either the data sources or the analysis logic.

## Knowledge Suggestion
LLM for Structured Data Extraction: A technique for crafting prompts that instruct a Large Language Model to return data in a specific, machine-readable format (e.g., JSON with predefined keys) from an unstructured text input. This is more powerful than simple text generation for data-driven applications.
