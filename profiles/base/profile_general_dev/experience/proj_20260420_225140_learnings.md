## Pattern: Modular CLI Application Design
Separating a command-line application into distinct modules for UI (user interaction), Parsing (input validation/interpretation), Logic (core functionality), and Orchestration (main loop) is highly effective. This improves testability, maintainability, and makes the system easier to extend.

## Pattern: Standard C++ Project Structure
Using a standard directory layout (`include/` for headers, `src/` for source files) and a modern build system like CMake is a best practice for C++ projects. It ensures portability and makes the project understandable to other developers.

## Anti-pattern: Monolithic Main Function
For interactive CLI tools, avoid placing all application logic (input reading, parsing, calculation, output) within the `main.cpp` file. This creates tightly coupled code that is hard to test and maintain. The final multi-module architecture successfully avoided this pitfall.

## Preference: Explicit Separation of Concerns
The design shows a clear preference for breaking down problems into smaller, single-responsibility modules (UI, Parser, Calculator) rather than a monolithic approach. This is a core tenet of robust software design.

## Preference: Modern C++ Toolchain
There is an implicit preference for using modern, standard tools for C++ development, specifically C++17 and CMake, over older or platform-specific alternatives.

## Knowledge Suggestion
For command-line tools that need to evaluate complex mathematical expressions (e.g., '3 + 4 * 2'), a simple parser is insufficient. Research the Shunting-yard algorithm to convert infix notation to a format like Reverse Polish Notation (RPN), which is then easily evaluated using a stack.
